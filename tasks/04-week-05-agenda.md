## Management skill (first part of the class)
A good project manager is good with agents. Before handing work to any agent, write the brief:
- **Goal.** What done looks like, concretely enough to check.
- **Scope.** What is in, what is out, which files it may touch.
- **Resources.** What you give it to get there: the folder and CLAUDE.md, reference files, tools and
  MCP connectors, the harness it runs in. This is context management from Week 04, aimed at one job.
- **Decision rights.** When to stop and ask you; what it may decide alone.
Students write one brief per project page; the main session hands each to a Sonnet agent. Review
afterwards asks two questions: did the agent miss, or did the brief?
Learning objective that transfers: the quality of delegated work is set by the brief.

## Ways of working with agents (second part)
Students meet multiple agents here, in the first half, on pages they already know. The week teaches
the ways to work with agents, each named for when to reach for it.

1. **Lead and builders.** The main session (Opus) hears the brief, two project pages, and spawns two
   Sonnet agents, one per page, to write the code in parallel. It does not write code itself; it
   reviews what comes back against the Week 04 design system, color first, then type and layout, and
   sends fixes back. Use when the work splits into parts and the judgment should stay in one place.
2. **Side chat, sent to main.** A side question (an image size, a CSS detail) goes in a side chat so the
   main session's context stays on the design. When the answer matters, send it back to main.
   Use when a question would clutter the main thread.
3. **Fork.** Two plausible directions for a page: fork the session, try both, keep one.
   Use when you would otherwise argue with yourself.
4. **Tasks folder, fresh session.** (Already taught in Week 02.) Write the work down in `tasks/`; a new
   session picks it up later. Use when the work spans days or sessions. Name it here as one of the
   ways for contrast; this week's steps use 1 to 3 and do not write to `tasks/`.

- Desktop app only: confirm each move (spawning Sonnet agents, side chat, send to main, fork) exists in
  the Code tab before writing the step. Students do not use the terminal.
- Learning objectives that transfer: separate who decides from who builds; review against a written
  standard; keep each conversation on one thing.
