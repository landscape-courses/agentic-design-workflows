REFERENCE
Glossary
The words this course uses, one line each · added to through the semester
Look a word up here when a page or Claude uses it. How Claude behaves, as opposed to what a word means, is on Claude Code 101.
GITVersions and GitHub
  • Repository (repo). A project folder whose whole history is kept. Your site is one; your Part II tool is another.
  • Git. The program on your computer that keeps a repository’s history. Claude runs it for you.
  • Commit. One saved version of the repository, with a message saying what changed.
  • Push. Sending your commits to GitHub. Until you push, a change exists only on your machine.
  • Pull. Bringing commits from GitHub down to your machine, such as work a cloud session did.
  • GitHub. A website that holds a copy of your repository online, shows its history, and is where work is handed in.
  • GitHub Pages. GitHub’s free hosting: it publishes the repository’s HTML as a live site at username.github.io.
  • Tag. A name pinned to one commit, such as week-03. The tagged commit is that week’s submission.
  • README. The file GitHub shows on a repository’s front page: what the project is, for a human reader.
  • Branch. A copy of the work that can change without touching main.
  • main. The branch that counts. On your site, main is what is live.
  • Merge. Bringing a branch’s changes into main.
  • Pull request (PR). A request to merge a branch, where the changes are shown for review before they go in.
  • Diff. The difference between two versions, line by line: what was added and what was removed.
WEBWhat a Website Is Made Of
  • HTML. The content and structure of a page: headings, text, images, links.
  • CSS. How the page looks: type, color, spacing, layout.
  • JavaScript. What the page does when someone clicks, scrolls or types.
  • Local preview. Your site opened from your own machine, to check a change before it is pushed.
  • URL. A page’s address on the web.
  • Markdown. Plain text with light marks (# for a heading, - for a list). CLAUDE.md, README and task files are written in it.
  • Design system. The written rules for how your site looks: type, grid, color, images. Claude follows it on every page.
AGENTWorking with Claude
  • Agent. An AI that acts: it reads files, runs commands and edits your folder, then checks what it did. A chat only answers.
  • Session. One conversation with Claude, in one folder. Every session starts blank.
  • Context. Everything Claude has read in the current session: your messages, files, command output.
  • Token. The unit Claude reads and writes in, roughly part of a word. Your plan’s usage is counted in tokens.
  • Model. Which Claude you are talking to. Opus plans and reviews; Sonnet builds from a clear brief; Haiku is fast for small jobs.
  • Effort. How hard Claude thinks before answering. Build on low, check on high.
  • Permission mode. How much Claude may do without asking. This course uses auto: ordinary work goes ahead, anything risky stops to ask.
  • Brief. What you hand an agent: the goal and what done looks like, the scope, the resources, and when to ask you.
  • CLAUDE.md. The file Claude reads at the start of every session: what the project is, where things are, the rules you have decided.
  • Memory. Notes Claude saves for itself when you correct it. Type /memory to read them.
  • tasks/ folder. Work written down as files, one task each, so a later session can pick it up.
  • Skill. A saved procedure, a folder holding a SKILL.md, that Claude loads when its job comes up.
  • Subagent. An agent the main session starts to do one job, such as building a page, and report back.
  • Side chat. A separate conversation for a side question, so the main session stays on the design.
  • Fork. A copy of a session at one point, to try a second direction without losing the first.
  • Cloud session. A session that runs on GitHub’s copy of your repository, on its own branch, while your laptop is closed.
  • MCP. A connector that lets Claude use another program, such as Rhino, Figma or a database.
  • Terminal. The text window where commands are typed. In this course you open it once, to sign in to GitHub.
