REFERENCE
Claude Code 101
Plain facts about how Claude Code works · added to through the semester
Each fact here explains something you will see the agent do. Read the list once now and come back when something surprises you. New facts are added as the course reaches them.
TOKENSWhere Your Usage Goes
  • Every message resends the whole conversation. Turn 40 costs far more than turn 4, because Claude reads all 39 turns before it again. A long session burns tokens quickly.
  • A pause makes the next message cost more. For a short while Claude can reuse what it already read at a discount. After a long break it rereads the whole conversation at full price.
  • Start fresh when you switch tasks. Type /clear or open a new session. Anything worth keeping belongs in a file, so a fresh session loses nothing.
  • Your plan refills on two clocks: a five-hour window from your first message, and a weekly limit. Both are on the usage page in the app’s settings.
  • Point instead of pasting. Naming a file lets Claude read only what it needs. Pasting puts the whole text into every later turn.
CONTEXTWhat Claude Knows
  • Every session starts blank. Claude knows what is in the folder and nothing from your last conversation.
  • CLAUDE.md is read at the start of every session. Keep it short, a map that points to other files. Each fact lives in one place, so it can never disagree with itself.
  • Claude keeps its own memory. When you correct it, it may save a note for next time. This is on by default. Type /memory to open the notes, read them, and delete what is wrong.
  • A new session is a fresh pair of eyes. It never saw the first session’s reasoning, which makes it a good reviewer of that session’s work.
CONTROLHow Claude Works
  • Auto is the default permission mode. Claude goes ahead with ordinary work and stops to ask before anything risky. Keep it on auto in this course.
  • Talk to it like a co-worker. A goal, why it matters, what good looks like, and how to check it beats a long list of rules.
  • Effort sets how hard Claude thinks before answering. Low is fast and cheap for quick back-and-forth. Raise it when a mistake would be easy to miss. Build on low, check on high.
  • A skill is a saved procedure. It is a folder holding a SKILL.md file, loaded only when its job comes up. Type / to see the ones you have.
