Two ways to do less by hand. A skill holds an instruction you keep giving. A cloud session works on a copy while you are away, and you read the difference before it goes live.
WORKSHOPSkills
01 Make a Skill from a Finished Chat
Said it three times? Make it a skill. Last week you gave Claude the image rule more than once. Paste:
prompt to Claude 
Turn how we handle images on this site into a skill called
web-images: the format, the size, where files go, and width and
height on every image. Save it in this project.
Test it on a new image:
prompt to Claude 
Add _source/<an image>.jpg to the <project> page.
  • Type / to see your skills.
  • When it misses, say: “Fix the web-images skill so this does not happen again.” The fix goes into the skill, where it lasts.
  • A skill is optional for the assignment. Make one when you notice you repeat yourself.
WORKSHOPBranches and How a Team Ships
  • main is what is live. Every push to it updates your site.
  • A branch is a copy you can change without touching main.
  • A team ships in five steps: a branch, a pull request, review and approval by someone else, automatic checks, then a merge into main. Each step exists because many people touch the same code.
  • Working alone, you keep three: work on a branch, read the diff, merge. You are the reviewer. A tiny fix can go straight to main.
WORKSHOPCloud Sessions
A cloud session runs on GitHub’s copy of your repository, on its own branch, and keeps working with your laptop closed. Several can run at once. The instructor shows one running on this course site. Remote control is the contrast: your own laptop, driven from your phone.
02 Write the Task
A cloud session sees only what is on GitHub, so the task has to be pushed. In Claude desktop:
prompt to Claude 
Add tasks/05-<name>.md describing one small change: <a third project
page, or a fix from last week's crit>. Commit and push it.
  • Pick something you can check in one look.
03 Start It from Your Phone
Open the Claude app on your phone, go to Code, choose your username.github.io repository, and send:
prompt to Claude 
Do tasks/05-<name>.md on a new branch. Open a pull request when it is
done.
Put the phone away. Check back in when it says it is done.
04 Compare with main
On GitHub, open the pull request and its Files changed tab. Read the diff the way you did in Week 3. To see the change, ask Claude desktop:
prompt to Claude 
Check out the branch from my latest pull request and open a preview.
Merge or ask for fixes Merge when it works and you would be fine with it live. Otherwise ask the cloud session for fixes on the same branch.
05 Merge
On the pull request, click Merge pull request, then confirm. Then in Claude desktop:
prompt to Claude 
Switch to main and pull.
Open https://username.github.io and check the change is live.
06 Hand It In
prompt to Claude 
Move the task to tasks/done/, commit and push. Tag the latest commit week-06 and push the tag.
Give the link to the instructor. It will be opened in class.
