Everything you make in this course lives in one Git repository on GitHub: your site, your specs, your Part II project. Git keeps every saved version. GitHub holds a copy online, publishes the site, and is where your work is handed in.
You open a terminal once, to sign in to GitHub. After that you work in the Claude desktop app, and Claude runs Git for you. Your job is to read what it is about to do and say yes or no.
01 Make a GitHub Account
Sign up at github.com/signup. Use a personal email, not your CCNY one: this account outlives the course, and so does your site.
Pick your username with care. It becomes your public address: username.github.io.
  • Short, lowercase, close to your real name. jsmith-design works; xX_studio_2027_Xx follows you around.
  • Turn on two-factor authentication when GitHub asks. An agent will be pushing to this account.
02 Open a Folder in Claude Desktop
Install the Claude desktop app and sign in with the account that has your paid plan.
In Finder or File Explorer, make a folder named after your GitHub username: username.github.io, with your own username. In the app, switch to the Code tab and choose that folder. Claude works on the folder you chose, and nothing outside it.
  • Keep it outside Dropbox, iCloud and OneDrive: sync tools and Git fight over the same files. Your home folder or Documents is fine.
03 Ask Claude to Install Git
From here on you talk and Claude runs the commands. Paste this:
prompt to Claude 
Check whether Git and the GitHub CLI are installed, and install
whatever is missing. Tell me when both are ready.
Claude asks before it runs each command. Read each one before you approve it. You do not need to know every flag; you need to know which ones only look at things and which ones change them.
  • Installing may pop up a system window (Apple's developer tools on macOS, an installer on Windows). Click through it, then tell Claude it is done.
04 Sign In to GitHub, in a Terminal
Signing in to GitHub is the one step Claude cannot do for you: the approval happens in your browser, on your account. It happens in a terminal. Open Terminal (macOS) or Command Prompt (Windows; search for cmd) and run:
both systems 
gh auth login
Choose GitHub.com, then HTTPS. When it asks Authenticate Git with your GitHub credentials?, answer Yes: that lets every push use this sign-in. Then choose Login with a web browser. Copy the one-time code, paste it into the page that opens, and approve. Wait for ✓ Logged in as …. The sign-in is saved for your whole computer, so Claude can use it from now on.
  • On Windows, a GitHub sign-in window may still appear on your first push. That is Git’s own sign-in; log in with the same account and it will not ask again.
05 Ask Claude to Make the Repository
Back in Claude desktop. Paste this, with your own name:
prompt to Claude 
Make this folder a Git repository. Write a README.md with my name,
[Your Name], and one sentence on what I hope to build this semester.
Commit it with the message "Start". Then create a public repository
on my GitHub account called [username].github.io and push to it.
Before you approve Which of Claude's commands change something outside this folder? Find it before you approve it.
The push. It changes GitHub, in public. Everything else stays in the folder.
  • Open github.com/username/username.github.io. Your README is there. That page is now public.
  • The name matters. A repository named exactly username.github.io becomes your site at https://username.github.io, with nothing after the slash. Already have one? Name this one website; the site then lives at username.github.io/website.
06 Tag It and Hand It In
A commit is a saved snapshot. A tag is a name pinned to one snapshot, and it is how every assignment in this course is handed in. Whatever the tag points at is what you submitted. GitHub records when you pushed it.
prompt to Claude 
Tag the latest commit ws01 and push the tag.
Check it on GitHub: on your repository page, open the branch menu and switch to the Tags tab. ws01 should be there.
  • Every milestone works the same way: D1, D2 and so on, pushed by the due date. Work you push after the tag is not part of the submission.
  • Resubmitting? Never move a tag. Push a new one with a suffix: D3-r1, then D3-r2. The latest one is graded; the original shows what was in by the deadline.
07 Email Your Repository
From your CCNY email, send the link to zzhang@ccny.cuny.edu. It will be opened in class, before you leave.
email 
Subject: Arch 51580 repo: [Your Name]

https://github.com/[username]/[username].github.io
  • Your repository is public, so the link is all the instructor needs to read it. Every milestone is read from here.
