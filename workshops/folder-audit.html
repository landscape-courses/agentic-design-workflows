Six weeks in, your folder holds a CLAUDE.md from Week 2, a design system from Week 4, a skill from Week 6, project pages, and tasks finished and abandoned. Rules got stated twice and drifted apart. Claude still follows lines you stopped meaning.
Today you read what the agent reads and make it say what you mean now. Then the site gets one more page: the home of your Part II project.
01 Ask Claude What It Thinks
Open your username.github.io folder in the Code tab of Claude desktop and start a fresh session. Ask:
prompt to Claude 
What is this project, how is it organized, and what rules do you
follow when you work on it? Answer from the files only.
Read the answer against what you mean today. Write every mismatch into _source/audit-notes.md: a rule you dropped, a page it does not know about, a folder it describes wrong.
  • The answer is a picture of what the agent reads. Where it is wrong, a file is wrong.
02 Read CLAUDE.md Yourself
Open CLAUDE.md and read every line. It was written in Week 2 and patched since. Mark three kinds of line in your notes:
  • Stale: a fact that was true in Week 3 and is not now.
  • Repeated: a rule that also lives in your design system or a skill, often worded differently.
  • Dropped: a rule you stopped following weeks ago.
03 Run the Audit
Now Claude reads the same files with your notes beside it. It proposes; you decide.
prompt to Claude 
Audit CLAUDE.md and the design system against the files in this
folder and my notes in _source/audit-notes.md.
- Cut anything you can learn by reading the files.
- Give each fact one home. Where a rule is stated twice, keep one
  and point to it from the other.
- Phrase every rule as what to do.
- Flag facts that no longer match the folder.
List every change with the line it touches and why. Apply nothing
until I approve.
  • CLAUDE.md loads into every session, so every line costs attention. Shorter is better when nothing you rely on is lost.
04 Review the Cuts
Go through the list one change at a time. Approve, reject, or reword in plain words. Then ask Claude to apply what you approved.
Catch this one A cut that removes a rule you rely on. Claude can only see what the files say, so it will cut a rule the files seem to cover. For each cut, ask: would a new session still do this right?
05 Clean tasks/
Open tasks need the same audit. Finished ones belong in tasks/done/; abandoned ones go.
prompt to Claude 
List every file in tasks/ with one line on whether it is done, open,
or abandoned, judged from the site as it is now. Move done ones to
tasks/done/. Ask me before deleting anything.
  • An abandoned task a fresh session picks up is a page you did not want, built carefully.
06 Check Again
Close the session, open a new one, and ask the question from step 01 again.
Check The answer should now match what you mean. Where it does not, fix the file and ask once more.
07 Add the Project Page
Part I built the site. Part II is your own project, and the site is where it lives. Add one page for it now, as a task:
prompt to Claude 
Add a task tasks/NN-project-page.md: a page projects/part-two.html
following the design system, linked from the home page. It holds my
Part II proposal: the problem, my current workflow, the track, and
what success looks like. Then do the task and open a preview.
Write the proposal in your own words; Claude places it. The page grows all of Part II: each milestone adds to it.
  • Rename part-two.html to your project’s name once it has one. Names are context.
08 Hand It In
prompt to Claude 
Commit everything except _source, push, then tag the latest commit
D6 and push the tag.
D6 is the whole midterm: the audited site, the project page with your proposal, and your AI Fluency certificate. Bring the link to the pin-up.
Feeds forwardIn Week 8 your workflow gets its own repository, with its own CLAUDE.md and tasks. It starts from the habits this audit taught.
