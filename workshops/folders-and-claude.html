Claude forgets every conversation when the session ends. The folder is what lasts. Today you set up a folder that tells a new session everything it needs: what the project is, where things are, and what to do next.
By the end of class your site is live: one page, your name, your photo, your bio. The rest of Part I builds on it.
01 Bring Your Material
Open your arch51580-site folder from Workshop 01. Inside it, make a folder called _source and put in what your site will draw on:
  • A photo of you, or one image of your work.
  • A short bio: a paragraph in a text file. Rough is fine; Claude will ask you about it.
  • Your CV, if you have one handy.
Give every file a name that says what it is. Claude reads names before it opens anything.
a folder Claude can read at a glance 
arch51580-site/
├─ README.md
└─ _source/
   ├─ portrait.jpg
   ├─ bio.md
   └─ cv.pdf
  • IMG_4471.jpg and bio final v2 (1).docx make Claude open every file to find out what it is. portrait.jpg and bio.md answer the question before it is asked.
02 Let Claude Write CLAUDE.md
Every Claude session starts blank. Last week’s conversation is gone; the files in the folder stay. So anything Claude should know next time goes into a file it reads at the start of every session: CLAUDE.md, at the root of the folder.
You talk, Claude writes it. Open the folder in the Code tab of Claude desktop and paste:
prompt to Claude 
Interview me about this website, one question at a time: who I am,
what the site is for, which pages it needs, and how this folder is
organized. Then write a CLAUDE.md at the root of this folder. Keep it
under 40 lines and show it to me before you build anything. Keep
_source out of Git; it holds originals.
Read what it wrote and correct it in words. The file is yours; Claude is the one typing.
Check Close the session and open a new one in the same folder. Ask: “What is this project, and how is it organized?” If the answer is wrong, fix the file, then ask again.
  • CLAUDE.md holds what Claude cannot work out by reading the files: what the site is for, the folder map, rules you have decided.
03 Make a tasks Folder
A conversation is good for steering today’s work. A task you want done later belongs in a file. Make a folder called tasks, and ask Claude to add the first one:
prompt to Claude 
Make a tasks folder. Add a file tasks/01-bio-page.md describing one
task: a single index.html page with my name, my photo from _source,
and my bio. Plain HTML and CSS in one file. Then add a line to
CLAUDE.md saying that open tasks live in tasks/ and finished ones move
to tasks/done/.
Open the task file and read it. Add anything you care about: a font you like, a site you admire, a color to avoid.
  • One task per file, numbered so the order is clear: 01-bio-page.md, 02-project-page.md.
  • Ideas you have between sessions go straight into tasks/. The folder becomes your to-do list, and Claude can read it.
04 A New Session Does the Task
Start a fresh session in the same folder. It knows nothing except what is in the files, which is the point.
prompt to Claude 
Read CLAUDE.md and tasks/. Do the first open task, open a preview,
and move the task to tasks/done/ when I approve it.
Look at the preview and correct it in plain words: a bigger name, a quieter color, more space around the photo.
Before you approve Did Claude follow CLAUDE.md and the task file, or only what you said in the chat? Look for one detail from the task file in the page.
  • Corrected the same thing twice? Ask: “Add that to CLAUDE.md.” The next session reads the file, so the file is where a decision lasts.
05 Push It
The page is on your laptop. Send it to GitHub:
prompt to Claude 
Commit everything except _source and push it.
Open github.com/username/arch51580-site and check that index.html and CLAUDE.md are there, and _source is not.
  • A public repository shows every file in it. Keep anything private out of the folder, or in _source, which Git now skips.
06 Turn On GitHub Pages
GitHub holds your files. Pages turns them into a website. Do this one by hand, once, so you know where the switch is:
  • On your repository page, open Settings, then Pages in the left column.
  • Under Build and deployment, set Source to Deploy from a branch.
  • Set the branch to main and the folder to / (root). Click Save.
  • Wait a minute or two and refresh. The top of the page shows Your site is live at and a link.
Open it: username.github.io/arch51580-site. Open it on your phone too. From now on every push updates the site within a minute or two.
  • Still a 404 after a few minutes? Check that the file is named exactly index.html, at the top of the repository. Pages looks for that name.
  • The Actions tab shows each publish as it runs. A red mark there means it failed; paste the message to Claude.
07 Hand It In
prompt to Claude 
Tag the latest commit D1 and push the tag.
Give the link to the instructor. It will be opened in class.
