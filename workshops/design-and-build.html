A good project manager is good with agents. You decide what gets built and whether it is good; agents do the building. The work comes back as good as the brief you wrote.
WORKSHOPThe Brief
01 Bring Two Projects
Put the material for two projects in _source, one folder each, named for the project:
folder 
_source/
├─ river-park/
│  ├─ plan.jpg
│  └─ text.md
└─ courtyard-study/
   ├─ model-01.jpg
   └─ text.md
  • A few images and a short paragraph per project is enough.
02 Write Two Briefs
Before handing work to any agent, write the brief. Four parts:
brief template 
Goal: a project page for <project>. Done means <what I will check>.
Scope: one new file, projects/<name>.html, and a link to it from
index.html. Touch nothing else.
Resources: CLAUDE.md, design-system.md, _source/<name>/, and
<a page I admire>.
When to ask: stop and ask me before adding a color, font or layout
that is not in the design system. Crop images on your own.
Then paste:
prompt to Claude 
Write tasks/03-<first project>.md and tasks/04-<second project>.md
from this brief template. Ask me one question at a time for anything
missing.
  • The goal says what done looks like, concretely enough to check. The scope says which files the agent may touch.
WORKSHOPA Lead and Its Builders
Four ways to work with agents, each for its own situation:
  • Lead and builders. The work splits into parts and the judgment should stay in one place.
  • Side chat. A side question would clutter the main thread.
  • Fork. Two directions are plausible and you would otherwise argue with yourself.
  • Tasks folder, fresh session. The work spans days. You met this in Week 2.
03 Spawn the Builders
Set the session’s model to Opus in the model menu. The lead plans and reviews; the builders write code. Paste:
prompt to Claude 
You are the lead on this site and you do not write page code. Spawn
two subagents on Sonnet at low effort, one per brief:
tasks/03-<first project>.md and tasks/04-<second project>.md. Run
them in parallel. When they report back, review both pages against
design-system.md, color first, then type, then layout, and list what
fails.
  • Build on low effort, check on high. Effort is part of the budget, like the model.
  • Every agent counts against your usage. Keep an eye on the five-hour window.
04 Side Chat for a Side Question
How big should the images be? That question would fill the lead’s context with detail. Open a second session in the same folder and ask it there:
prompt to Claude 
What format and size should images on a portfolio site be? Give me
one rule I can follow, in one line.
When the answer matters, bring the rule back to the lead:
prompt to Claude 
Use this image rule for both pages: <the rule>.
  • This course site’s own rule: AVIF, long edge 1920px at most, width and height on every image.
05 Review and Send Fixes
prompt to Claude 
Send each builder the fixes for its page, then review both again.
When a page misses Ask: did the agent miss, or did the brief? If the brief never said it, fix the brief and run it again.
06 Fork to Compare
Unsure between two directions for one page, say one full-width image or a grid of three? Try both:
prompt to Claude 
Fork this session. In the fork, try <the second direction> on the
<project> page.
Compare the two previews, keep one, and close the other session.
  • Starting a new task? Type /clear or open a fresh session. A long conversation costs more with every message.
DISCUSSIONDesk Crits
Show your two pages. Name one thing the brief got right and one thing it missed.
07 Hand It In
prompt to Claude 
Move both tasks to tasks/done/, commit and push. Tag the latest commit week-05 and push the tag.
Give the link to the instructor. It will be opened in class.
Feeds forwardEvery job you hand off in Part II starts as a brief like these. When work comes back wrong, check the brief first.
