WORKSHOPChecking the Agent’s Work
01 Read Your Page
Open your username.github.io folder in the Code tab and paste:
prompt to Claude 
Open a preview of index.html. Then walk me through the file region
by region: for each part I can see on the page, show me the HTML that
makes it and the CSS that styles it. Keep each part short.
  • You are learning to find things, not to write them: point at a line and say what it does.
02 Write the Spec
Last week you described the page in words. Today you name the values. Paste:
prompt to Claude 
Interview me, one question at a time, about the type, grid and color
of my site. Use the terms from Graphic Design 101 and offer options
with real values: font families, a size scale, column count and
gutter, a palette of three to five named hex colors. Then write
tasks/02-type-grid-color.md with every value I chose.
  • “Clean” cannot be checked. “Body 18px, line height 1.6, color #222” can.
  • Show Claude a site whose type you admire as an example.
03 Apply It and Read the Diff
prompt to Claude 
Do tasks/02-type-grid-color.md. Do not push yet. When you are done,
show me the diff and explain each change in one line.
A diff lists each file that changed: lines removed in red, lines added in green. Read it against the spec, then look at the preview.
Before you approve Find one value from the spec in the diff, such as one hex color. If it is missing, Claude skipped it.
04 A Check That Passes or Fails
“Looks good” is not a check. Ask for one that can fail:
prompt to Claude 
Write a checklist from tasks/02-type-grid-color.md, one line per
value, each marked pass or fail. Run it against the site: read the
CSS, open the preview at desktop and phone width, and give me the
evidence for each line. Keep the checklist in the task file.
  • Evidence is the line of CSS or a screenshot, not a sentence about it.
  • Kept in the task file, the checklist can be run again after every change.
05 A Second Session Reviews
Start a fresh session in the same folder and paste:
prompt to Claude 
Review the site against the checklist in tasks/02-type-grid-color.md.
You did not build it. Report each line pass or fail with evidence,
and list anything the spec asks for that the site does not do.
Why a new session It never saw the first session’s reasoning, so it judges the result, not the intention.
06 Push and Check Live
prompt to Claude 
Fix what failed, then commit and push.
Open https://username.github.io on your laptop and your phone and compare it with the preview.
  • The live site can take a minute or two to update. A hard refresh (Ctrl+Shift+R, or Cmd+Shift+R on a Mac) loads the new version.
07 Hand It In
prompt to Claude 
Move the task to tasks/done/. Tag the latest commit week-03 and push the tag.
Give the link to the instructor. It will be opened in class.
